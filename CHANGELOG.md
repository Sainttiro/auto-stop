## [2.9.14] - 2025-11-21

### 🔧 Исправлено
- **CRITICAL: Исправлена логика закрытия SHORT позиций с Multi-TP**
  - **Проблема:** При срабатывании TP для SHORT позиции система неправильно определяла операцию
  - **Было:** BUY для SHORT = увеличение (усреднение) ❌
  - **Стало:** BUY для SHORT = уменьшение (закрытие) ✅
  - **Реальный кейс:**
    - SHORT 100 лотов SBER
    - Сработал TP1 → BUY 50 лотов (должно закрыть 50)
    - Система решила: "BUY + SHORT = усреднение" ❌
    - Вместо: 100 - 50 = 50 лотов
    - Делала: 100 + 50 = 150 лотов ❌
    - Выставляла ордера на 150 / 2 = 75 лотов ❌
  - **Решение:**
    - Исправлена логика в `position_manager.py` (строки 638-642)
    - Для SHORT: SELL = усреднение, BUY = закрытие
    - Для LONG: BUY = усреднение, SELL = закрытие
  - **Результат:** SHORT позиции теперь корректно закрываются при срабатывании TP

### 📚 Документация
- Обновлен CHANGELOG.md с информацией о критическом исправлении
- Обновлен CRITICAL_FIXES.md с подробным описанием бага

## [2.9.12] - 2025-11-12

### 🔧 Исправлено
- **CRITICAL: Исправлена проблема с дубликатами сообщений от API Tinkoff**
  - **Проблема:** API иногда отправляет одно и то же сообщение `OrderTrades` несколько раз
  - **Пример:** Купил 1 лот, через 3 секунды API отправил то же сообщение → система обработала как покупку еще 1 лота
  - **Последствия:** 
    - Неправильное количество в позиции (2 лота вместо 1)
    - SL/TP выставлялись на неправильное количество (3 лота вместо 2)
    - Риск овер-селла при срабатывании ордеров
  - **Решение:** 
    - Добавлен словарь `_processed_orders` для отслеживания обработанных `order_id`
    - Проверка дубликатов: если `order_id` обработан менее 10 секунд назад - пропускаем
    - Автоматическая очистка старых записей (TTL = 5 минут)
    - Детальное логирование предотвращенных дубликатов
  - **Результат:** Каждый ордер обрабатывается ровно один раз, позиции всегда корректны

- Обновлен CHANGELOG.md с информацией о критическом исправлении

## [2.9.8] - 2025-11-10

### 🔧 Исправлено
- **CRITICAL: Исправлена race condition между TradesStream и PositionsStream**
  - **Проблема 1 (GMKN):** Позиция удалялась между выставлением ордеров и setup Multi-TP
    - Последовательность: выставлены ордера → PositionsStream удалил позицию → ошибка "Позиция с ID 7 не найдена"
    - Решение: Добавлена проверка существования позиции перед `setup_multi_tp_levels()`
    - Результат: Если позиция удалена, операция пропускается с логированием события
  
  - **Проблема 2 (MTLR):** Позиция удалялась во время обновления количества
    - Последовательность: найдена позиция → рассчитано новое количество → позиция удалена → ошибка при обновлении
    - Решение: Метод `_update_position_unlocked()` теперь возвращает `None` если позиция удалена
    - Добавлена обработка `None` в `update_position_on_trade()` с логированием события
  
  - **Новый тип события:** `RACE_CONDITION_PREVENTED` для отслеживания предотвращенных race conditions
